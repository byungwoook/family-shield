# Family Shield v3

## 방향: Direct Answer

라임, 잉크, 크림은 유지하고 앱의 중심을 문서형 결과지에서 가족과 실시간 요청으로 옮겼어요. 사람이 먼저 보이고, 지금 할 일이 다음에 보이도록 설계했어요. 같은 크기의 행을 모든 화면에 반복하지 않고 홈의 작업 모듈, 진행 화면의 타이머, 결과 화면의 인증된 답변이라는 서로 다른 주인공을 뒀어요.

기존 v1과 v2는 그대로 보존했고 이 폴더에 새로 만들었어요. 저장소 `/tmp/fs`의 앱 문자열과 `docs/PRODUCT_REDESIGN.md`는 읽기 전용 참고예요. 앱 코드 수정, 커밋, 푸시, 실제 요청 전송은 하지 않았어요.

## 내비게이션과 화면 구조

### 3개의 루트 탭
- **홈**: 새 요청 확인 또는 현재 열려 있는 요청으로 바로 진입하는 작업 시작점.
- **확인 기록**: 날짜별 완료 내역. 결과 단어와 이름을 보고 다시 열기.
- **가족**: 등록된 실제 가족, 확인 수단, 초대와 설정. 온라인 상태나 위치 추적은 제공하지 않아요.

세 루트에서만 탭을 유지해 길을 잃지 않게 했어요. 진행, 결과, 음성 공유, 자녀 답변은 별도 집중 흐름이며 뒤로 가기나 닫기로 복귀해요. 자녀 역할은 보호자용 3개 탭을 보여 주지 않아요.

### 화면별 주인공
| 화면 | 가장 먼저 볼 것 | 다음 행동 |
|---|---|---|
| 홈 기본 | 음성 파형과 메시지 확인 진입이 묶인 잉크 모듈 | 메시지 확인하기 |
| 확인 중인 홈 | 기존 모듈을 대체한 지우의 열린 건과 큰 01:08 | 진행 상황 보기 |
| 진행 상세 | 64pt 카운트다운과 앱 알림, 본인 확인 후 답변, 전화의 3단계 | 기다리기. 돈 보내지 않기 |
| 사기 의심 결과 | 지우의 아바타와 인증된 아니요 응답 | 공유 시트를 열어 가족에게 경고 |
| 확인된 결과 | 같은 사람의 인증된 예 응답 | 직접 이야기하라는 안내를 읽고 완료 |
| 확인 기록 | 날짜와 이름, 금액, 결과가 묶인 기록 | 해당 건 다시 열기 |
| 가족 | 보호자와 자녀 각각의 사람 프로필 | 자녀 추가 또는 관리 |
| 자녀 답변 | 엄마가 물은 요청과 300만원 | 예 또는 아니요 선택 후 Face ID로 제출 |
| 음성 공유 | 이미 첨부된 음성과 받을 자녀 | 대상 선택 후 명시적으로 확인 요청 |

확인 중인 건은 홈 위에 배너를 덧붙이지 않고 같은 히어로 자리를 바꿔 써요. 가족과 최근 확인은 계속 남아 홈의 방향감이 유지돼요. 부모와 자녀의 이니셜 마크는 홈, 진행, 답변, 기록에서 이어져요.

### 시그니처 순간
결과는 잉크색 전체 화면으로 전환돼요. 자녀의 큰 직접 답변이 사람 옆에 나타나고, 이어서 판정과 다음 행동이 보여요. 빨간 응답을 자녀 얼굴에 덮거나 자녀를 사기범처럼 표시하지 않아요. 초록 또는 빨강은 AI 점수나 목소리 분석이 아니라 인증한 자녀의 예 또는 아니요에만 붙어요.

## 레퍼런스 PDF에서 가져온 것

실제 PDF의 크림 `#F3F0E9`, 잉크 `#0D1015`, 라임 `#D6FE39`, 전체 잉크 표면과 얇은 선, 음성 파형, 작게 쓰는 영문 모노 라벨만 가져왔어요. 프레젠테이션 글꼴은 참고하지 않았고 모든 한글 UI는 Pretendard예요. 파형은 음성 메시지의 입구와 미리듣기에만 쓰며 음성 진위 판별 장식으로 쓰지 않아요. 키패드는 실제 전화 앱의 입력 단계에만 있어야 하므로 요청받지 않은 가짜 앱 내 키패드를 결과 화면에 장식으로 넣지 않았어요.

## 타입

Pretendard Variable 1.3.9를 각 HTML에 데이터 URL로 내장했어요. 한글 시스템 폰트 대체가 아니라 실제 Pretendard가 렌더링됐는지 CDP로 확인해요. 모노는 작은 영문 맥락 라벨에만 시스템 mono를 사용해요.

| 역할 | 크기 / 줄 높이 pt | 굵기 |
|---|---|---|
| 진행 타이머 | 64 / 76 | 600 |
| 홈의 라이브 타이머 | 44 / 50 | 600 |
| 자녀 요청 금액 | 42 / 52 | 650 |
| 전체 화면 판정 | 38 / 46 | 700 |
| 기록, 가족, 자녀 질문 제목 | 32 / 40 | 700 |
| 홈 인사 및 현재 작업 | 26 / 36 | 700 |
| 히어로 제목 | 24 / 31 | 600 |
| 섹션과 사람 이름 | 20 / 28 | 650 |
| 주 본문과 행동 | 17 / 26, 버튼 17 / 24 | 400, 버튼 650 |
| 보조 본문 | 15 / 22, 14 / 21 | 400~500 |
| 제한된 캡션 | 13 / 20, 탭 12 / 16 | 500 |
| 영문 eyebrow | 12 / 18 | 500 |

큰 한글 제목은 자간 -0.75~-1.3pt, 본문은 -0.35pt예요. 숫자는 tabular-nums로 흔들림을 막아요. 실제 SwiftUI와 Compose 구현에서는 Dynamic Type와 fontScale을 적용하고 큰 글자에서 세로 스크롤을 허용해야 해요. 이번 PNG는 기본 글자 크기 스냅샷이며 확대 글자 접근성 검증을 대신하지 않아요.

## 그리드, 표면, 컴포넌트

- 화면: 390 × 844pt. 출력 PNG: 780 × 1688px.
- 상태 바 44pt, 내비게이션 44pt, 홈 인디케이터 안전 영역 34pt.
- 루트 탭은 49pt와 하단 안전 영역 34pt, 총 83pt. y=761에서 시작해요.
- 좌우 여백 20pt, 기본 간격 8, 16, 24, 32, 40pt. 복합 행의 아이콘과 텍스트 간격은 12pt, 표면 안쪽은 16 또는 20pt예요.
- 집중 화면의 바닥 행동은 x=20, y=734, w=350, h=56. 가족 탭에서는 탭 위로 올려요.
- 히어로 반경 26pt, 그룹 24pt, 보조 건 20pt, 버튼 16pt, 작은 타임라인 노드 10pt. 그림자 대신 표면 차이와 0.5pt 구분선만 사용해요.
- 아바타는 실제 사람에게만 둥글게 사용해요. 버튼 옆 모든 아이콘에 원형 배경을 붙이지 않아요.
- Lucide 공식 SVG를 일관된 1.5pt 스트로크로 사용해요. 시스템 상태 바만 표준 채움 아이콘이에요.
- 주 행동은 화면당 하나예요. 자녀의 예/아니요 타일은 선택 컨트롤이며 제출 버튼이 아니에요.
- 구현 시 모든 탭, 뒤로 가기, 닫기, 짧은 링크의 터치 영역은 최소 44 × 44pt. 보이는 링크 글자 크기와 히트 영역은 구분해야 해요.
- 상태 이름, 직접 답변, 아이콘과 순서를 함께 사용해 색만으로 상태를 구분하지 않아요.

## 데이터와 제품 규칙

1. 인증된 답변만 결과를 바꿔요. AI, 파형, 발신번호, 무응답, 시간 초과로 초록이나 빨강이 되지 않아요. 확인됨이어도 송금을 권하지 않아요.
2. 스크린샷은 서로 다른 상태의 예시예요. 홈의 열린 지우 건과 기록의 완료된 지우 건을 동시에 중복해서 표시하지 않았어요. 기기 시계는 예시로 12:23~12:25 CT이며 실제 확인 기록이 아니에요.
3. 01:08은 요청 후 22초가 지난 시점의 90초 전환 기한이에요. 서버의 실제 `push_deadline`에서 남은 시간을 계산해야 해요. 막대는 90초 시간축을 약 3초 단위로 표시하는 보조 시각화이며 신뢰도, 분석률, 생체 확인률이 아니에요. 자동 전화가 금지된 상태에는 카운트다운 대신 실제 상태를 보여야 해요.
4. 앱에서 알림을 보냈다는 것과 자녀가 열거나 Face ID를 진행했다는 것은 달라요. 본인 확인 후 답변은 다음 단계라는 뜻이에요. 관측하지 못하는 원격 Face ID 진행을 애니메이션으로 꾸며 내지 않아요.
5. 전화는 기존에 등록하고 인증한 4821 끝자리로만 해요. 메시지에서 추출한 번호로 걸지 않아요. 24시간 이내 바뀐 번호에서의 전화상 예 응답은 초록이 아니라 노랑이에요.
6. 자녀 화면의 엄마, 선영, 요청 금액, 음성 출처는 현재 자녀용 응답 데이터보다 확장된 UI 제안이에요. 구현하려면 권한이 확인된 API가 요청한 가족 구성원과 해당 건의 맥락을 제공해야 해요. 엄마라는 이름을 의심스러운 메시지에서 추출해 인증된 부모처럼 보여서는 안 돼요. 금액은 메시지의 주장 또는 보호자가 확인한 값이지 검증된 송금 정보가 아니에요. 실제 제공 값이 없으면 해당 요소를 숨기고 일반 질문을 사용해요.
7. 공유 진입 화면의 미리듣기는 제출 전 로컬 파일이에요. 진행 화면의 원본 재생은 현재 백엔드가 받아쓰기 후 파일을 지우는 정책과 별개인 디자인 제안이에요. 구현 전에 기기 내 한시 보관과 삭제 시점을 정해야 하며 서버 원본 보존을 추가하지 않아요. 원본이 없으면 재생 버튼 없이 텍스트 맥락만 보여요. 파형은 예시이며 실제 렌더링 시 로컬 원본 샘플에서 생성해야 해요.
8. 자녀 선택 화면은 아니요가 선택된 중간 상태를 보여 줘요. 실제 첫 상태는 무선택이며 제출 비활성. 선택과 Face ID 제출을 분리한 UI 제안이며 실제 앱의 인증 절차 변경은 구현하지 않았어요. 닫기나 인증 취소는 열린 상태를 유지해요. 알림 자체에 예/아니요 제출이나 비밀 코드를 넣지 않아요.
9. 가족에게 경고 공유는 OS 공유 시트를 여는 동작이에요. 앱이 가족에게 자동 발송하지 않아요. 이 목업 제작 중 실제 공유나 전송은 없었어요.
10. 영어 Face ID는 iOS 스냅샷의 네이티브 기능 이름이에요. Android에서는 BiometricPrompt와 기기 인증 정책에 맞는 한국어 표현으로 바꿔요. 앱 내 화면 구조와 토큰은 두 플랫폼에서 공유하되 시스템 바, 뒤로 가기, 공유 시트는 각 플랫폼 것을 사용해요.

### 문자열 출처
`family_verify_message`, `family_recent_heading`, `family_add_child`, `case_dont_send`, `cd_status_green`, `cd_status_yellow`, `child_yes`, `child_no`는 실제 한국어 문자열을 사용했어요. `open_waiting_push`, `result_not_sent`, `result_sent`, `new_case_not_sent_yet`, `child_question`은 의미를 유지하며 짧게 다시 썼어요. 사기 표시는 신중한 언어로 사기 의심으로 다듬었어요. 자세한 원문은 `/tmp/fs/android/app/src/main/res/values-ko/strings.xml`이에요.

## 렌더와 점검

- `build.py`는 개별 HTML 13개를 만들어요. 모든 한글 폰트와 아이콘을 내장해 외부 네트워크 없이 열려요.
- `render.cjs`는 Chromium으로 @2x PNG를 만들어요.
- `audit.cjs`는 상태 바, 내비게이션, 20pt 왼쪽 정렬, 390pt 밖의 내용, 탭과 본문의 겹침, 하단 안전 영역, 아이콘 스트로크, 주 행동 개수, 한글 Pretendard 실제 사용과 금지 문장 부호를 검사해요.
- `boards.py`, `boards.cjs`는 비교표와 개요 이미지를 만들어요.
- `document.py`는 이 문서와 실제 대비 계산을 갱신해요.
- `iterations/00-first`, `iterations/01-hierarchy`, `SELF_REVIEW.md`에 두 차례 수정 과정과 자기 검토를 남겼어요. 최종 13개 화면은 각각 전체 해상도로 다시 열어 확인했어요.
- 개별 13개 화면은 기본 크기에서 잘림과 겹침이 없는지 확인했지만 사용성 테스트나 코드 구현 완료를 주장하지 않아요.
